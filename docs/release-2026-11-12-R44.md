# R44：开场背景一致性修复

R43在背景模块超过1.5秒准入窗口时先揭开旧场景，随后在开场运镜结束后自动创建并替换背景。慢模块对照在Chrome桌面和WebKit移动视窗中均复现一次可见的旧→新切换，并伴随入场长帧。本轮只修改启动顺序，不更换着色器、模型、贴图、分辨率或交互功能。

- 在importmap之后预加载背景模块，使下载与原加载过程重叠；真正GPU初始化仍在准备遮罩内执行。
- 初次准备共用一个最多8秒的异步准入窗口。已有默认warm调用仍为1.5秒；已开始的同步GPU工作无法由计时器中断。
- 准备开场远景相机后，先更新背景，再合成第一帧，避免近景背景与远景瓷器错位。
- 取消入场后的自动安装重试。模块超时或失败时保持可用的兼容场景；用户明确点击“观黑洞”仍走原有准备流程。原生WebGL上下文恢复保留原逻辑。

CPU检查覆盖共同截止时间、迟到回调拒绝、首帧调用顺序与稳定回退。冷启动对照覆盖正常、背景模块延迟3秒、模块失败和延迟15秒超时；完整交互回归的39个阶段均通过，覆盖隐藏界面、截图、四件展品、黑洞往返和上下文恢复；38组CPU脚本及98项语法检查通过。

本轮记录的是Mac上的浏览器引擎与移动视窗，不能代替iPhone/Android微信真机，也不保证所有设备在固定2K复杂画面中全程60fps。回退基线为R43提交c11dc9859c091f126e97e0bed5af0e38e0f9641b。
