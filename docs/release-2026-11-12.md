# R43：主展馆同场景观测与界面隐藏

原展馆中直接使用完整黑洞、星空与星云。同一相机连续切换“观黑洞／观瓷”，保留当前展品、语言、介绍状态和同一个画布。观测面板按当前对象切换，原四件展品和创意工坊继续使用现有资源。

## 观测与操作

- 黑洞观测面板提供“隐藏界面”。隐藏后，右上角保留“显示界面”入口，镜头和坠入过程继续；恢复后显示当前读数与必要的视界提醒。
- 事件视界提醒独立于可滚动参数面板，提供回到轨道入口。模拟按原路径停在1.04 rₛ，未实现或宣称真正跨越事件视界。
- 修复近视界暂停／继续时OrbitControls最小距离夹紧导致的镜头跳位，以及生成PNG时回到轨道又恢复旧坠入状态的问题。
- 隐藏和恢复不改变相机、参数、PNG输入锁或截图归属；退出、上下文丢失及加载失败会清理恢复入口。

## 性能修正

暂停稳定后完成16帧重建，然后复用已有背景纹理，每帧仍正常合成画布。手动移动、参数变化、窗口变化及继续播放会重新采样。PNG仍独立积累24帧。暂停、预设、坠入及参数回滚都显式重启采样窗口，避免旧画面残留。

界面只在值变化时写DOM，隐藏期间停止数字读数更新。恢复时读取当前状态。没有减少模型、贴图、原光线步数或更换黑洞算法，也未新增运行依赖或远程资源。

曾实验缓存渲染目标完整性检查。虽然CPU采样显示同步查询耗时减少，但固定2K的帧时间结果没有可靠改善，因此已撤回；发布版继续使用原验证路径。实验记录保存在工程work目录，不随站点发布实验代码。

## 验证与限制

CPU脚本检查、语法检查与实际浏览器回归均在发布前完成。重点专项可直接运行：

```sh
node tests/starfield-ui-visibility.cjs
node tests/starfield-paused-render.cjs
node tests/starfield-plunge.cjs
node tests/starfield-core.cjs
```

实际浏览器矩阵包括Chrome桌面、WebKit移动视窗和Chrome安卓设备配置。检查隐藏／恢复、焦点、坠入终点、稳定暂停的画面复用、PNG、横竖屏、四件展品及原生WebGL上下文恢复。原始报告和源码哈希在本地交付的checks目录。

这些是Mac本机浏览器引擎和设备配置测试，不是实体iPhone、Android或微信真机验证。帧时间受GPU、设备负载和画质设置影响；固定2K压力测试仍出现过长帧，不能承诺所有设备、视角和参数全程60fps。默认自动画质保留原有预算策略，输出画布与背景实际重建尺寸分别显示。
